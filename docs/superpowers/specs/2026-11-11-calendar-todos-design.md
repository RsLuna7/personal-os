# 日历待办设计文档

- 日期：2026-11-11
- 状态：已实施
- 前置：[日历月视图设计文档](2026-11-11-calendar-design.md)。本文改写其中的月网格、新建和拖动部分，其余（路由、翻月、月份范围、`month.ts`）不变
- 范围：新增“待办”数据；日历页改为只显示待办和节点的卡片格子。时间线页和板块页不动

## 1. 目标

日历上原来画的是跨天的阶段色块和学期带，适合看“这段时间在做什么”，但不适合回答“这一天要做什么”。时间线已经承担了前者，所以日历改成按天的待办视图：每天一张卡片，卡片里是当天的待办和节点。

## 2. 数据

### 2.1 待办

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 字符串 | 与其他数据的 id 不能重复 |
| `title` | 字符串 | 去掉首尾空白后 1 到 40 个字，规则同其他名称 |
| `date` | `YYYY-MM-DD` 或 `null` | `null` 表示“未安排” |
| `done` | 布尔 | 是否完成 |
| `laneId` | 字符串或 `null` | 所属板块；`null` 表示不挂板块 |
| `createdAt` | ISO 时间字符串 | 创建时间，只用来稳定排序 |

可选字段一律用 `null`，不用“缺省”。原因：store 的去重靠 `JSON.stringify` 比较，补丁用展开合并，备份要经过 JSON 来回，缺省字段在这三处都容易出错。

第一版不做重复任务、子任务、优先级、备注。

### 2.2 版本和迁移

- 数据版本由 2 升到 3，`AppData` 多一个 `todos: Todo[]`。
- 迁移 2 → 3：加 `todos: []`。旧数据和旧备份都会自动升级，升级前原数据另存为 `personal-os:data:backup-v2`（现有机制）。
- 校验：`laneId` 不为 `null` 时必须指向存在的板块；待办 id 参与全局 id 查重；`createdAt` 必须是可解析的时间。

### 2.3 store

`addTodo`、`updateTodo`、`toggleTodo`、`removeTodo`，都走 `commit`，各进入一步撤销。

`removeLane` 不再删除待办：同一次提交里把该板块名下待办的 `laneId` 置为 `null`。所以删除板块是一步撤销，撤销后板块和待办的挂靠一起恢复。

备份导入导出、本地存储、示例数据都带上 `todos`。示例数据加了几条待办：有日期的、未安排的、已完成的、挂板块的、不挂板块的，另有一天放了 4 条用来演示格子内滚动。

## 3. 日历月视图（画法 A：卡片加色条）

### 3.1 格子

- 一周一行、七格一行，每天是一个独立的圆角卡片，格子之间留小间隙，不画表格线。每次显示完整的周，周一起，和之前一样。
- 日期数字在格子左上；条目沉在格子底部。
- 非本月的日期淡出，但仍可操作。
- 今天：虚线边框，颜色用 `--today`，不给整格上色。所有格子都有一圈同宽的透明边框，所以今天的边框不会让内容位移。
- 没有任何板块也显示网格（待办不依赖板块）。原来“没有板块就显示空状态”的规则取消。

### 3.2 条目

- **待办**：一条细竖色条加标题。色条用板块颜色；不挂板块用中性灰。完成后标题变淡加删除线，色条变灰，仍留在格子里。
- **节点**：小菱形加名称，和待办的竖条明显不同；颜色用板块色。仍可点开编辑、拖动。
- 悬停或聚焦在待办上时，右侧出现勾选控件。

### 3.3 一格里的顺序与溢出

一天的条目按下面的顺序排，这个顺序同时决定“第一条未完成待办”：

1. 节点在前，按板块顺序，同板块按 id。
2. 待办在后：未完成的在前、已完成的在后；其内按板块顺序（不挂板块的排最后）、创建时间、id。

已完成的排在后面，是为了放不下时被收起的是已完成的，而不是还要做的。代价是勾选后这条会在格子里往下挪一位。

一天的条目全部画在格子里，节点在前、待办在后。格子高度固定，能直接看到 3 条左右；装不下时条目列表在格子里上下滚动（鼠标放在格子上滚轮即可），不画滚动条，上面或下面还有内容时那一侧的边缘淡出作为提示。最初的方案是折成“还有 N 项”按钮加弹出层，后来按用户意见改成滚动，弹出层已删除。

### 3.4 格子底色

- 这天有未完成待办：格子染成**排序后第一条未完成待办**所属板块的浅色（`--lane-fill`）；那条待办不挂板块，则用中性的浅色。
- 没有待办，或全部已完成：中性灰底。
- 只有节点不染色。

为了能在不加载样式的测试里验证，格子带 `data-tint`：`none`（中性灰底）、`neutral`（中性浅色）或板块颜色名。条目永远带自己的 `data-lane-color`（挂板块用板块色，不挂用 `neutral`），所以不会继承格子的颜色。

### 3.5 拿掉的东西

跨天的阶段色块及其排布计算（`layout.ts`）、学期带、在日历上新建和拖动阶段（拖选区间、拖两端）、“最近用过的板块”（`lastLane.ts`：新待办默认不挂板块，不再需要）。学期数据和学期编辑仍然保留给时间线用。

## 4. 交互

以下默认做法由我替使用者定下，用了之后觉得不顺手可以改。

| 事项 | 默认做法 | 说明 |
|---|---|---|
| 新建 | 在格子空白处**双击**；键盘上在选中的日期格按 `Enter` | 新建一条无板块的待办，标题“新待办”，立即打开编辑面板并选中标题 |
| 勾选 | 点条目右侧的勾选控件；键盘上焦点在条目上按 `空格` | 一步撤销 |
| 编辑 | 点条目文字（或焦点在条目上按 `Enter`）打开编辑面板 | 面板有标题、日期、板块、完成、删除；沿用现有编辑面板的样式和行为 |
| 改期 | 拖到别的日期格；键盘上焦点在条目上按 `←` `→` 移一天、`↑` `↓` 移一周 | 一次拖动一步撤销；`Esc` 或拖出网格取消 |
| 删除 | 焦点在条目上按 `Delete`，或面板里的“删除” | 底部有“撤销”提示条 |
| 未安排 | 日历右侧的“未安排”列表 | 见 4.1 |

- 单击空白格子不再新建任何东西（以前单击会新建节点，容易误触）。
- 在日历上不再新建节点，节点由顶栏“添加”菜单和板块页新建；日历上的节点仍能点开编辑、拖动、用方向键和 `Delete` 操作。
- 日期格的方向键、`PageUp`、`PageDown`、`T` 不变。
- 键盘把条目移到当前月以外的日期时，页面跟着翻到那个月并把焦点放回这条；条目找不到时焦点回到那一天的格子。条目获得焦点时浏览器会把它滚进格子的可见范围。
- 勾选有一个很轻的过渡（颜色、删除线、色条的淡入淡出，约 150 毫秒），沿用 `tokens.css` 里统一的“减少动态效果”处理：系统开启后所有过渡时长归零。

### 4.1 未安排列表

- 列出所有 `date` 为 `null` 的待办，未完成在前；每行同样有勾选控件，点文字打开编辑面板。
- 顶部有输入框，输入标题回车，新建一条未安排的待办（不挂板块，不打开面板）。
- 支持把条目**拖进某天的格子**（拖动代码里“按下时不在网格内”一支改动很小，所以做了）：拖动过程中该条目会预览在悬停的格子里，松手才写入；移回网格外松手则取消。
- 在编辑面板里清除日期，待办回到“未安排”列表；设日期则出现在对应格子。

## 5. 编辑面板

新增 `TodoEditor`，结构与 `MilestoneEditor` 一致（`EditorPopover`、名称草稿、关闭时保存、删除提示条）。对共用字段做了向下兼容的扩展：

- `NameField` 可改标签文字（待办叫“标题”）。
- `DateField` 可选地允许为空（传 `optional`，不再提示“请填写日期”），不传时行为不变。清空输入框、或原生日期框没输完时给出的空值不会写入数据（否则改日期改到一半，待办就跳进“未安排”了），失焦后恢复成数据里的日期；清除日期只有面板里的“清除日期”按钮这一个明确操作。
- `LaneSelect` 可选地加一项“不挂板块”，不传时行为不变。

面板贴着条目：条目在格子里就贴它，开始编辑时先把它滚进格子的可见范围；未安排的待办贴在列表里的那一行；日期被改到网格以外的月份时，页面翻到那个月，面板跟着走（沿用现有逻辑）。

## 6. 代码结构

```
src/features/calendar/
  cells.ts            纯函数：一天的条目、排序、溢出、格子底色、未安排列表
  month.ts            不变
  drag.ts             只留指针换算成日期和拖动阈值
  useCalendarDrag.ts  待办和节点的移动（含从未安排列表拖入）
  useCalendarKeys.ts  日期格和条目的键盘
  CalendarPage.tsx    页面：顶部、网格、未安排列表、编辑面板
  MonthGrid.tsx       网格容器
  DayCell.tsx         一个日期格
  TodoItem.tsx        待办条目和勾选控件
  MilestoneItem.tsx   节点条目
  UnscheduledList.tsx 未安排列表
src/features/editor/TodoEditor.tsx
```

删除：`layout.ts`、`WeekRow.tsx`、`lastLane.ts` 及对应测试。边界约定不变：`cells.ts`、`month.ts`、`drag.ts` 是纯函数；日期换算只用 `days.ts`。

## 8. 验收清单（需要在浏览器里看的）

- [ ] 格子的圆角、间隙、底色深浅、今天的虚线边框看起来舒服
- [ ] 板块的八种颜色做格子底色和色条时都清楚；中性灰与“无待办”的灰底能分得出
- [ ] 勾选的过渡自然；系统开启“减少动态效果”后没有过渡
- [ ] 窗口宽 1024 像素时网格和右侧“未安排”列表都不挤
- [ ] 一格有 4 条以上时格子内滚动和边缘淡出
- [ ] 拖动手感（待办、节点、从未安排拖进格子）
- [ ] 持续集成全部通过，脚本体积不超过 200 KB

## 9. 已知风险

- 双击新建比单击稳，但第一次点开编辑面板时，如果紧接着在别的格子上双击，面板会先关闭再新建一条。可以接受。
- 勾选后条目在格子里下挪一位（见 3.3），颜色底色也可能随之变化（第一条未完成待办变了）。这是有意的，但第一次用可能意外。
- 样式没有在浏览器里看过（交给使用者验收）；测试通过属性验证规则，不验证像素。
