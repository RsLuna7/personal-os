# 日历月视图设计文档

- 日期：2026-11-11
- 状态：已实施；其中月网格、新建和拖动部分已被[日历待办设计文档](2026-11-11-calendar-todos-design.md)取代（日历不再画阶段和学期）
- 前置：[第一版设计文档](2026-11-10-personal-os-v1-design.md) 第 12 节第 2 项“日历月视图”；[板块详情页设计文档](2026-11-11-lane-detail-design.md)
- 范围：顶栏“日历”这一页。数据结构不变（版本仍是 2），不需要迁移

## 1. 目标

补上时间线不擅长的事：**按具体日期看，并直接在日期上规划**。时间线是年尺度的，一眼看不出“下周三有什么”；日历把阶段、节点、学期放在月历里，并且是第二个主要的编辑入口。成功标准：

- 一个月内每一天有哪些阶段、节点、学期，一眼能看清；放不下的能展开看全。
- 能在日历上新建阶段（拖选区间）和节点（单击一天），能拖动改期、改长度，规则和时间线的编辑保持一致（撤销、校验、编辑面板）。
- 翻月、刷新、后退、复制链接都停在同一个月。

### 已确认的决定

| 事项 | 决定 |
|---|---|
| 页面用途 | 完整的日历式规划：查看，加上新建、拖动、改期 |
| 新建方式 | 在日期格上拖选区间新建阶段，单击一天新建节点 |
| 实现方式 | 自己用 CSS 网格和指针事件实现，不引入日历库（脚本体积上限 200 KB，样式和编辑规则要和现有页面一致） |
| 编辑方式 | 复用现有的 `PhaseEditor`、`MilestoneEditor` 和 store 操作，不另写一套 |
| 吸附 | 日历按**天**吸附；时间线按周吸附的规则不变 |

### 本版不做

- 周视图、日视图、议程列表
- 拖到月份边缘自动翻月（可以拖到网格里显示的上月、下月日期）
- 在日历上跨板块拖动（换板块在编辑面板里）
- 重复事件、提醒、导出日历文件
- 手机端适配（最小宽度 1024 像素不变）

## 2. 数据与状态

- **数据结构不变**，版本仍是 2。日历只读写现有的 `phases`、`milestones`、`terms`。
- **界面状态**（不进数据、不进撤销历史、不保存）：当前拖动的状态；“最近在日历上用过的板块”，刷新后重置，没有时取 `order` 最小的板块。
- 所有修改走现有 store 操作（`addPhase`、`updatePhase`、`addMilestone`、`updateMilestone`、`removePhase`、`removeMilestone`），每次操作进入撤销历史；一次完整的拖动只算一步。

## 3. 路由

- `#/calendar` 和 `#/calendar/<年-月>`，例如 `#/calendar/2026-11`。其他路由不变。
- `useHashRoute` 的参数由 `modules` 扩展到 `calendar`；`calendar` 的参数是 `YYYY-MM`。
- 参数缺失、格式不对、月份不存在（如 `2026-13`）、年份不在 1900 到 2100 之间：显示当前月，不报错。
- 翻月就是改网址，所以浏览器的后退、刷新、复制链接都有效。顶栏“日历”在 `#/calendar` 和 `#/calendar/<年-月>` 下都高亮。

## 4. 页面

沿用全局页和板块页的视觉：画布底色、白色卡片加柔和阴影、Inter 加思源黑体，标题用思源宋体。

### 4.1 顶部

“‹ 2026年11月 ›”：左右按钮翻月；旁边“今天”按钮回到当前月。到达 1900 年 1 月或 2100 年 12 月时对应方向的按钮禁用。

### 4.2 月网格

- 周一为一周的开始，和时间线一致。表头是“一 二 三 四 五 六 日”。
- 每次显示**完整的周**：从包含当月 1 日的那一周的周一，到包含当月最后一天的那一周的周日，4 到 6 周（2027 年 2 月就是 4 周）。当月以外的日期淡化，但可以点击和拖到。
- 今天的日期格有明显标记（沿用今天线的颜色）。
- **学期**：用一条细带标在每个周行的顶部，颜色和命名规则沿用时间线；学期结束日不含当天。
- **阶段**：跨天的色条，颜色沿用板块色。已结束的变淡，进行中的实心，待确认的虚线，规则同时间线。阶段跨周时在每个周行里各画一段，**只有第一段（或当月网格里首次出现的那一段）带名称**，其余段只有颜色。
- **节点**：日期格里的圆点加名称，颜色按板块。
- 每个周行有 3 个“槽”（行）。先不限槽数，把这一周里的项目依次排进最靠前的空槽：阶段色条在这一周里占同一个槽，按板块顺序、再按开始日期排，互不重叠；节点占它所在那一天的最靠前的空槽。
- 第 1、2 槽的项目照常显示。第 3 槽：这一天没有项目落在第 4 槽及以后时，照常显示第 3 槽的项目；否则这一天的第 3 槽改显示“+N 项”，N 是这一天落在第 3 槽及以后的项数（包括第 3 槽原本那一项，所以 N 至少是 2）。第 4 槽及以后的项目不画。一个阶段色条在第 3 槽时，只在没有被“+N 项”占用的那些天画，所以可能被分成几段。
- “+N 项”：点开是该日的完整列表（阶段和节点按板块顺序排），点其中一项打开编辑面板。列表用现有的弹出层，`Esc` 关闭。
- 没有任何板块时显示空状态（同全局页），不显示网格。

## 5. 交互

### 5.1 新建

- 在**空白日期格**上按住并拖过几天再松开：新建一个阶段，范围是拖过的日期（含首尾，可以反向拖）。存储的结束日期是半开区间，即最后一天加一天。拖动过程中显示半透明预览。
- 在空白日期格上**单击**（没有拖动，或移动小于约 4 像素）：新建一个节点，日期是这一天。
- 新建后立即打开编辑面板，名称已选中。板块默认是“最近在日历上用过的板块”，没有时取排第一的板块；面板里可以换板块（换了之后记住）。
- 单击已有的色条或圆点是**选中并打开编辑**，不会新建。
- 误建的处理：`Ctrl+Z` 一步撤销，面板里也有“删除”。
- 说明：单击建节点容易误触（比如想点空白取消选中）。按已确认的决定先做单击，使用后如果觉得烦，改成双击是很小的改动。

### 5.2 拖动

- **阶段**：拖色条中间，整体平移，长度不变；拖左右两端的把手，改开始或结束日期。最短 1 天。
- **节点**：拖到别的日期格，改日期。
- 阶段跨周时，从哪一段开始拖都可以：移动量是“指针所在日期”减“按下时的日期”，所以可以跨周行拖动。
- 拖动过程中画预览，**松手时才写入数据**，整次拖动只算一步撤销。
- 按 `Esc`、把指针拖出日历区域后松手，或被拖的项在拖动中被撤销、删除、所在板块消失：取消这次拖动，数据不变，不报错。
- 指针移动小于约 4 像素算单击，不算拖动。

### 5.3 选中

点色条或圆点选中它（和时间线共用 `selection`），选中的项有明显的边框。点空白日期格是新建，不是取消选中；取消选中用 `Esc`。

## 6. 键盘

- 焦点在日期格上：方向键移动一天或一周；`Enter` 新建节点（等于单击）；`PageUp`、`PageDown` 翻月；`T` 回到今天。日期格是一张网格，同一时刻只有一个格子在 `Tab` 顺序里（roving tabindex）。
- 焦点在色条或圆点上：`Enter` 打开编辑；选中后 `←`、`→` 移动一天，`Shift+←`、`Shift+→` 改结束日期一天（阶段最短 1 天）；`Delete` 删除并显示底部“撤销”提示条；`Esc` 取消选中。
- 撤销重做：`Ctrl+Z`、`Ctrl+Shift+Z`，沿用现有的 `useUndoKeys`。
- 输入框、文本框、选择框、可编辑元素里不响应任何快捷键（沿用 `isTyping`）。

## 7. 代码结构

新增 `features/calendar/`，其余尽量复用：

```
src/
  app/
    useHashRoute.ts     参数扩展到 calendar（YYYY-MM）
    App.tsx             calendar 路由挂上 CalendarPage
  features/
    calendar/
      month.ts          纯函数：生成月网格、阶段按周切段并排行、每格的“+N 项”
      drag.ts           纯函数：指针坐标换算成日期，移动和缩放的日期计算
      useCalendarDrag.ts 拖选、拖动、取消的状态机
      CalendarPage.tsx  页面：顶部、网格、编辑面板
      MonthGrid.tsx     网格和表头
      WeekRow.tsx       一个周行：学期带、色条、节点
      ItemBar.tsx       阶段色条和节点圆点（选中、把手）
      DayOverflow.tsx   “+N 项”的列表弹出层
```

边界约定沿用前两版：`month.ts` 和 `drag.ts` 是纯函数，不碰 DOM、不碰 store；`features/calendar` 只发出修改意图（调用 store 操作）；编辑面板仍由 `editorStore` 控制，`CalendarPage` 像 `Timeline` 和 `LanePage` 一样渲染它们。日期换算只用 `days.ts` 的 ISO 字符串与整日数函数，不用带时区的 `Date`。

## 8. 出错处理

| 情况 | 处理 |
|---|---|
| 网址里的月份参数不合法或超出 1900 到 2100 | 显示当前月，不报错 |
| 没有任何板块 | 空状态，不能新建 |
| 拖动把阶段缩到小于 1 天 | 按 1 天截住，不写入非法数据；`store` 的校验是最后一道保险 |
| 拖动中被拖的项被撤销、删除或所在板块消失 | 取消这次拖动，数据不变，不报错 |
| 指针拖出日历区域后松手 | 取消，数据不变 |
| 同一天项目很多 | 折叠成“+N 项”，列表里看全 |
| 夏令时、跨年 | 只用 ISO 字符串和整日数运算，不经过带时区的 `Date` |
| 编辑面板里把项目换到别的板块 | 项目仍在日历上，只是颜色变了；面板不丢失定位（沿用板块页修复后的做法：同一个项始终是同一个元素） |

## 11. 已知风险

- **单击建节点容易误触。** 见 5.1；有 `Ctrl+Z` 和面板里的“删除”兜底，必要时改成双击。
- **自己实现拖动，手感要在浏览器里反复调。** 纯函数部分有测试保护；指针命中、阈值、预览要靠最后的验收和使用调整。
- **日历和时间线是两个编辑入口，规则必须一致。** 都走同一套 store 操作和编辑面板；唯一有意的差别是日历按天吸附、时间线按周吸附，已在文档里写明。
- **一个月内项目很多时界面拥挤。** 靠“+N 项”折叠；如果实际使用中仍然拥挤，再考虑按板块筛选（不属于本版）。
