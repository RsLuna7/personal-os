# 个人 OS 第一版设计文档

- 日期：2026-11-10
- 状态：待审阅
- 范围：第一版（v0.1.0），只做首页全局时间线
- 修订：2026-11-11，「全局」页改为仪表盘（第 2 节），视觉加重并自带字体（第 4、6 节）；这些修订在 v0.1.0 之后，见 CHANGELOG 的“未发布”

## 1. 目标

一个长期使用、持续迭代的个人规划系统。考研、四级、期末、实习等各自是一个板块，共用同一套内核。使用者是长周期、低强度的备考方式，需要一眼看清"现在处在哪个阶段、后面有什么"。

第一版的成功标准：打开固定网址，能在一张泳道时间线上增删改所有板块、阶段和节点，操作顺滑，数据不丢。

### 已确认的决定

| 事项 | 决定 |
|---|---|
| 形式 | 自建网页，电脑端优先 |
| 首页主角 | 全局页：“现在”摘要、时间线卡片、板块概览；完整的泳道时间线点“展开”进入 |
| 代码托管 | GitHub 公开仓库 `RsLuna7/personal-os` |
| 打开方式 | GitHub Pages：`https://rsluna7.github.io/personal-os/` |
| 数据 | 页面上直接编辑，存在浏览器本地；仓库里不含个人数据 |
| 技术路线 | React + TypeScript + Vite，时间线自绘（不使用甘特图库） |
| 风格 | 暖色纸感，分层卡片，有分量；不做深色模式 |
| 迭代方式 | 每次改动一个 PR，使用者确认后合并 |

### 第一版不做

- 日历、板块详情、今日三个视图（导航里占位，显示"待开发"）
- 任务清单、完成百分比、打卡
- 手机端适配、多设备同步、账号
- 深色模式
- 把时间线导出为图片或打印

## 2. 页面布局

### 全局页（`#/home`，默认首页）

在 1024 像素以上的窗口里，从上到下三块，画布底色比卡片深一档：

1. **“现在”摘要带**：今天的日期和星期；有几个阶段在进行（一个都没有时这一项不显示）；下一个节点的名称、所属板块、日期和“N 天后”徽章。没有即将到来的节点时这一项不显示。
2. **时间线卡片**：标题、缩放三档、“回到今天”、“展开”；卡片里是只读的时间线，不能拖动、聚焦、打开编辑面板，没有键盘快捷键，但可以平移和缩放，悬停提示仍然可用。高度最多 420 像素，超出后卡片内竖向滚动。
3. **板块概览**：每个板块一张小卡，顶部是板块色带加板块名；主体是当前阶段名、进度条（按日期计算，已过天数占总天数）、“第 N 天 / 共 M 天 · 还剩 K 天”；底部是下一个节点（带倒计时）和下一阶段（带开始日期）。没有进行中的阶段时写“暂无进行中阶段”。

规则：

- 同一板块同时有多个进行中的阶段时，已确定的优先于待确认的，再取开始更早的。
- 没有任何板块时不显示这三块，显示空状态（见第 3 节“首次打开”）。
- “展开”打开 `#/timeline`（完整的可编辑时间线，即下面“完整时间线”一节），顶栏的“全局”保持高亮，点它回到全局页。
- 板块概览的卡片暂时不能点击，等板块详情页做出来再接。

### 完整时间线（`#/timeline`）

从上到下三层：

1. **顶栏**：左侧产品名和四个导航项（全局、日历、板块、今日）；右侧"添加"按钮和"⋯"菜单。导出、导入收在"⋯"菜单里。
2. **时间标尺**：年份刻度，加一条学期带（大三上、寒假……）。放大到一定程度后显示月份刻度。未设置学期时只显示年月。
   - **以周为主**（2026-11-12）：一周宽于约 17 像素（每天 2.5 像素以上）时，每周一画一条比月线淡的竖线；一周宽于 56 像素（每天 8 像素以上）时，标尺多一行周刻度。周刻度在学期内写“第 N 周”（学期开始那天所在的周是第 1 周，学期重叠时用开始得晚的那个），学期外写周一是几号。名字里带“假”字的一段（寒假、暑假、假期……）算假期，不数周，也写周一是几号。
3. **泳道区**：每个板块一行，左侧是板块名，右侧是该板块的阶段和节点。最后一行是"添加板块"。

一条橙色竖线标出今天，贯穿所有泳道。页面打开时自动滚动到今天附近，顶栏有"回到今天"。

### 三种元素

| 元素 | 含义 | 外观 |
|---|---|---|
| 阶段 | 一段时间 | 圆角色块，块内显示名称；色块太窄时名称写在右侧（不压到同一行的下一个阶段，放不下就只靠悬停提示） |
| 待确认阶段 | 尚未确定的安排 | 同色虚线框，无填充 |
| 节点 | 某一天的事件 | 圆点，旁边显示名称 |

已经结束的阶段自动变淡（换用同一色带更浅的一级，不用透明度），当前和未来的阶段保持原色。

同一板块内时间重叠的阶段自动错开成两小行，不互相遮挡。

## 3. 交互

### 编辑

- **平移**：拖动色块中部，整体移动。
- **改起止**：拖动色块左右边缘。
- **吸附**：拖动和方向键都按整周挪动，保持原来是星期几（2026-11-12 起；之前拖动会吸到周一）。新建阶段从本周一开始，阶段最短一周。精确到天的日期在编辑面板里填，拖动不会把它改回周一。
- **拖动提示**：拖动过程中在色块上方显示实时的起止日期和总周数。
- **新建阶段**：在泳道空白处双击，生成一个四周长的色块并直接进入重命名。
- **新建节点、板块**：通过"添加"按钮。
- **编辑面板**：单击色块或节点弹出。阶段可改名称、起止日期、所属板块、是否待确认、备注；节点可改名称、日期、所属板块、备注。面板内有删除。
- **板块管理**：点击板块名弹出菜单，可改名、换颜色、上移、下移、删除。删除板块会连同其阶段和节点一起删除。
- **学期标尺**：点击学期带进入编辑，可增删改各段的名称和起止日期。

### 撤销与重做

- 所有修改都可撤销：`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做，历史保留最近 100 步（仅当前会话）。
- 删除不弹确认框，而是在底部出现"已删除，撤销"提示条，5 秒后消失。

### 键盘

| 按键 | 作用 |
|---|---|
| `Tab` | 在色块和节点间移动焦点 |
| `Enter` | 打开编辑面板 |
| `←` `→` | 选中项前后移动一周 |
| `Shift+←` `Shift+→` | 调整选中阶段的结束日期 |
| `Delete` | 删除选中项 |
| `Esc` | 关闭面板或取消选中 |
| `T` | 回到今天 |

### 浏览

- **缩放**：三档预设（近三个月、一年、全部），以及 `Ctrl+滚轮` 连续缩放，以鼠标位置为中心。
  - 打开页面、点档位、点“回到今天”，今天都在画布左起四分之一处。
  - “全部”至少显示一年；数据跨度不到一年时让数据居中。
  - 画布宽度一变（拖窗口、开关侧栏，或在主页卡片和完整时间线之间切换）就按当前档位重新适配，让“一年”始终是一年。主页卡片最宽只到 1280 像素的版心，宽屏上比完整时间线窄很多，所以两边各按自己的宽度适配，共用“今天在左起四分之一”的位置；展开时比例的变化被今天线和色块的入场动画盖住。自定义缩放（`Ctrl+滚轮`）不受影响。
- **平移视图**：横向滚轮，或按住空白处拖动。
- **悬停提示**：阶段显示起止日期和时长；节点显示日期和"还有 N 天"或"已过 N 天"。

### 首次打开

没有任何数据时显示空状态：一句说明加两个按钮，"从空白开始"和"载入示例"。示例是一套虚构的占位数据，用来熟悉操作，可一键清空。

## 4. 视觉规范

### 颜色

采用 Radix Colors 的 12 级色带，按固定对照表取色：

| 用途 | 取色 |
|---|---|
| 页面底色 | 暖灰（sand）第 1 级 |
| 全局页画布 | sand 第 3 级 |
| 卡片底色 | 白色，加柔和阴影（`--shadow-card`） |
| 标尺、面板底色 | sand 第 2、3 级 |
| 分隔线、边框 | sand 第 6 级 |
| 次要文字 | sand 第 11 级 |
| 主要文字 | sand 第 12 级 |
| 阶段填充 | 板块色带第 3 级 |
| 阶段边线 | 板块色带第 7 级 |
| 阶段文字 | 板块色带第 12 级 |
| 当前阶段（正在进行、已确定） | 实心：板块色带第 11 级做底，白色文字 |
| 已结束阶段 | 填充第 2 级，边线第 5 级，文字取第 11、12 级的中间色 |
| 节点圆点 | 板块色带第 9 级 |
| 今天线 | 橙色带第 9 级 |

板块可选 8 条预设色带：iris、tomato、teal、amber、blue、grass、pink、bronze。颜色只用于区分板块，不做装饰。

对比度（WCAG 相对亮度公式实测，八条色带都满足）：阶段文字（第 12 级配第 3 级底）不低于 10:1；实心阶段的白字（配第 11 级底）不低于 4.5:1。第 11 级文字配第 3 级底只有 4.10 到 5.41，所以阶段文字不用第 11 级。

### 排版

- 字体：正文用 Inter（数字和英文）加思源黑体（中文）；标题和大数字用思源宋体。都是可变字重字体，随应用一起发布（`@fontsource-variable`，按需下载中文切片），不依赖在线字体服务。字体未加载好时先显示系统字体。数字使用等宽数字样式。
- 字重：正文 400、500；标题和强调 600、700。系统字体里微软雅黑没有中间字重，所以不再依赖它。
- 字号：正文 12、14、16；标题 18、20、22；大数字 26 像素。
- 间距按 8 像素的倍数。泳道行高 56 像素，色块高 32 像素。
- 圆角：色块 6 像素，弹出面板 12 像素，全局页的卡片 16 像素。
- 层次：全局页的卡片靠底色深浅和柔和阴影浮起，不再靠边线；弹出面板仍用细边线；泳道之间不画横线，改为隔行浅底；不使用渐变。

### 动效

- 时长 150 到 250 毫秒，缓出曲线。
- 拖动实时跟手（每帧更新，不加过渡）；松手后 150 毫秒落到整周。
- 面板淡入并上浮 4 像素；缩放时色块平滑伸缩。
- 新建和删除有 200 毫秒的出现、消失过渡。
- 无循环装饰动画。系统开启"减少动态效果"时关闭全部过渡。
- 主页时间线卡片点“展开”进入完整时间线（2026-11-12 应用户要求加入，是第 4 条“装饰与动效”允许的例外）：
  - 用 View Transitions，卡片和完整时间线是同一块“时间线面”。卡片从原位置放大铺满内容区，约 480 毫秒，四角从 16 像素圆角收成直角；页面其余部分同时淡出淡入。
  - 放大落定后，今天线从上往下画出（延迟 360 毫秒，约 460 毫秒），各泳道的阶段色块从左往右展开（第 i 条泳道延迟 480 + 70×i 毫秒，最多错开 8 条），节点随后淡入。整套约 1.1 秒，期间可以正常操作。
  - 从完整时间线回到主页（顶栏右侧的“收起”按钮、顶栏的“全局”或浏览器后退）时反过来缩回卡片，不播放今天线和色块的入场。“收起”在 1024 像素以下只显示图标。
  - 浏览器不支持 View Transitions，或系统开启“减少动态效果”时，直接切换，没有动画。

### 前端界面生成原则

唯一判断标准：页面上的每一段文字、每一个元素，是否帮助用户完成当前操作。不能则不放。

#### 1. 页面文字白名单
页面上直接展示的文字仅限以下几类：
- 核心内容，以及标题、标签、按钮文字等操作必需的文案
- 数值与单位
- 空状态提示
- 缺失/错误提示，以及不可逆操作前的确认或警告

底层逻辑、使用说明、限制条件、前提假设不属于以上任何一类，一律写入独立的文档或帮助页，不得在页面中出现，更不得跨页面重复。

#### 2. 需要补充信息时的处理顺序
按顺序选择，前一种可行就不用后一种：
1. 不加。先确认去掉后用户是否仍能完成操作。
2. 在标题或关键区域旁放一个 info 图标，链接到对应文档章节。
3. 使用 tooltip、折叠面板或开关后展示。
4. 以上都不适用时才允许在页面内写文字，限一句话。

约束：
- 只有图标的元素必须带 aria-label。
- 移动端没有 hover，tooltip 必须可通过点击触发。

#### 3. 布局不可被破坏
任何新增内容不得造成以下情况：
- 文字异常折行
- 容器被撑开
- 任一视口宽度下出现横向滚动

出现任一情况时，按第 2 条顺序降级为更轻量的形式，仍无法解决则移除该内容。

#### 4. 装饰与动效
- 默认不使用渐变、装饰性图形、装饰性文字和入场/循环动画，除非现有设计规范已包含或用户明确要求。
- 交互反馈只用 hover/active/focus 的颜色、背景或边框变化，不使用位移、缩放、弹跳类动画。

#### 5. 必须实际预览验证
生成或修改视觉样式后，必须实际渲染并检查，不得仅凭代码推断渲染宽度与折行效果：
- 视口：桌面全宽（≥1440px）和移动端（375px）
- 语言：支持多语言时，中文和英文各检查一遍
- 检查项：折行、溢出、横向滚动、元素重叠

无法预览时必须明确告知"未经预览验证"，不得声称已验证。

#### 6. 适用范围
修改已有页面时，以上规则只约束本次新增或改动的部分。发现已有内容违反规则时，列出并询问，不擅自删除。

## 5. 数据结构

```ts
type ISODate = string // 'YYYY-MM-DD'

interface Lane {
  id: string
  name: string
  color: LaneColor   // 8 条预设色带之一
  order: number
}

interface Phase {
  id: string
  laneId: string
  name: string
  start: ISODate     // 含当天
  end: ISODate       // 不含当天（半开区间），界面上显示为前一天
  tentative: boolean // true 时画成虚线框
  note: string
}

interface Milestone {
  id: string
  laneId: string
  name: string
  date: ISODate
  note: string
}

interface Term {
  id: string
  name: string
  start: ISODate
  end: ISODate       // 不含当天
}

interface AppData {
  schemaVersion: 1
  lanes: Lane[]
  phases: Phase[]
  milestones: Milestone[]
  terms: Term[]
  lastExportAt: string | null
}
```

### 存储

- 规划数据存在 `localStorage` 的 `personal-os:data` 键下；缩放档位等界面偏好存在 `personal-os:ui` 键下，不进入备份。
- 每次修改后 300 毫秒内自动保存。

### 版本升级

- 数据带 `schemaVersion`。应用启动时若发现旧版本，按顺序执行升级函数（1→2、2→3……）直到最新，再写回。
- 升级前把旧数据另存一份到 `personal-os:data:backup-v{旧版本号}`，升级失败可恢复。

### 导出与导入

- 导出：下载一个 JSON 文件，内容是完整的 `AppData`，文件名 `personal-os-YYYY-MM-DD.json`。
- 导入：先校验结构和版本，通过后整体替换当前数据。导入可撤销。
- 距上次导出超过 30 天时，"⋯"菜单上显示小圆点。从未导出过的，从第一次使用那天起算。

### 出错处理

| 情况 | 处理 |
|---|---|
| 本地数据读不出来或校验失败 | 不覆盖、不清空；显示错误页，提供"下载原始数据"和"导入备份" |
| 导入文件格式不对 | 拒绝导入并说明原因，现有数据不变 |
| 导入文件版本比应用新 | 拒绝导入，提示先刷新页面获取新版 |
| 浏览器存储已满或被禁用 | 顶部显示警告条，提示立即导出 |

## 6. 技术方案

| 层面 | 选择 |
|---|---|
| 构建 | Vite |
| 界面 | React + TypeScript（严格模式） |
| 样式 | Tailwind CSS v4 |
| 周边控件 | shadcn/ui（按钮、弹出面板、菜单、输入框、提示条） |
| 颜色 | `@radix-ui/colors` |
| 字体 | `@fontsource-variable/inter`、`noto-sans-sc`、`noto-serif-sc`，自带、按需加载 |
| 状态 | Zustand，撤销历史自行实现 |
| 数据校验 | Zod |
| 日期计算 | 自行实现的整日数运算（按 UTC 计），不引入日期库 |
| 时间线绘制 | 绝对定位的 HTML 元素，便于文字截断、键盘焦点和面板定位 |
| 测试 | Vitest + React Testing Library |
| 代码规范 | ESLint + Prettier |
| 路由 | 哈希路由（`#/home`、`#/timeline` 等），避免 Pages 刷新后 404 |

具体版本号在实施时以各项目当时的稳定版为准。

```
    editor/            编辑面板、板块菜单、学期编辑
  data/
    schema.ts          类型和 Zod 校验
    store.ts           状态、撤销重做
    persistence.ts     读写 localStorage
    migrations.ts      版本升级
    backup.ts          导出导入
    sample.ts          示例数据
  styles/
    tokens.css         颜色对照表、间距、字号、动效参数
  components/ui/       shadcn 组件
```

边界约定：

- `features/timeline` 只读数据、发出修改意图，不直接碰存储。
- `data/` 不依赖任何界面代码，可以单独测试。
- 换算、分行、吸附是纯函数，不依赖 React。
- 以后新增视图是在 `features/` 下加目录，并在 `app/` 的路由里挂上。

## 8. 工程规范

按成熟开源项目的常规做法：

- **README**：一句话介绍、截图、在线地址、数据存储和备份说明、本地开发方法。
- **许可证**：MIT。
- **版本号**：语义化版本，从 `v0.1.0` 开始；每个版本打标签。
- **更新日志**：`CHANGELOG.md`，按"新增、变更、修复"记录。
- **提交信息**：约定式提交（`feat:`、`fix:`、`docs:` 等）。
- **PR**：每个 PR 只做一件事，使用模板写明改了什么、如何验证、界面改动附截图。
- **待办**：使用者的反馈和后续想法记为 GitHub Issue，用标签区分"体验问题"和"新功能"。
- **持续集成**：每次提交和 PR 自动执行代码检查、类型检查、测试、构建，任一失败则不能合并。
- **发布**：主分支通过检查后由 GitHub Actions 自动构建并部署到 Pages。

## 9. 体验底线

- 拖动和缩放全程不掉帧（目标每秒 60 帧，50 个阶段以内）。
- 首屏在普通宽带下 1 秒内可操作；打包后的脚本压缩后不超过 200 KB（字体文件不计入，它们按需下载）。
- 所有操作可用键盘完成，焦点清晰可见。
- 文字与底色的对比度达到 WCAG AA。
- 最小支持宽度 768 像素（2026-11-12 从 1024 下调）；更窄时横向滚动，手机端尚未适配。
- 支持最近两个大版本的 Chrome 和 Edge。

## 11. 已知风险

- **数据只在一个浏览器里。** 清除浏览数据或换电脑会丢失，唯一的保护是导出备份。后续可通过云同步解决。
- **GitHub Pages 在国内访问不稳定。** 如果影响日常使用，可以改为其他静态托管，但网址变化后需要导出再导入一次数据。
- **仓库公开。** 代码对所有人可见；个人规划不在仓库里，示例数据必须保持虚构。
