# 板块详情页设计文档

- 日期：2026-11-11
- 状态：已实施
- 前置：[第一版设计文档](2026-11-10-personal-os-v1-design.md) 第 12 节第 1 项“板块详情页”
- 范围：顶栏“板块”这一页，加上数据版本升级到 2

## 1. 目标

用一个板块自己的页面，按列表（而不是拖色块）查看和管理它的所有阶段和节点，并存放这个板块的备注和资料链接。成功标准：

- 能从顶栏“板块”或主页的板块概览卡进入某个板块的页面。
- 在页面里能新增、修改、删除该板块的阶段和节点，能写备注，能增删改资料链接。
- 旧版（版本 1）数据和备份都能无损升级，升级前有备份。

### 已确认的决定

| 事项 | 决定 |
|---|---|
| 页面重心 | 两者都要：列表式管理阶段和节点，加上备注和资料链接 |
| 页面结构 | 左侧板块列表，右侧所选板块的详情，一页完成，不分两级 |
| 数据方案 | 备注和链接放在板块（`Lane`）上，不单独建集合 |
| 编辑方式 | 复用现有的阶段、节点编辑面板，不另写表单 |

### 本版不做

- Markdown 备注、链接的图标或预览
- 阶段级、节点级的链接
- 拖动排序链接、拖动排序阶段
- 完成勾选、打卡、进度手动调整
- 手机端适配

## 2. 数据

### 2.1 结构（版本 2）

```ts
interface Link {
  id: string
  title: string // 1 到 40 字，同 NAME_MAX
  url: string // 只允许 http: 和 https:
}

interface Lane {
  id: string
  name: string
  color: LaneColor
  order: number
  note: string // 新增，最多 2000 字（同 NOTE_MAX），纯文本
  links: Link[] // 新增，最多 50 条
}

interface AppData {
  schemaVersion: 2 // 原为 1
  // 其余不变
}
```

### 2.2 校验

- `Link.url` 必须能被解析为 URL，且协议是 `http:` 或 `https:`；`javascript:`、`data:`、`file:` 等一律拒绝。校验写在 Zod 结构里，所以导入的备份也会被检查。
- 链接的 `id` 与其他实体的 `id` 一起做全局唯一检查（沿用现有规则）。
- 纯函数 `normalizeLinkUrl(text): string | null`（放在 `data/links.ts`）：去掉首尾空白；没有协议时补 `https://`；协议不是 http 或 https 返回 `null`；其余返回规范化后的网址。界面输入和校验共用它。

### 2.3 升级 1→2

- 在 `migrations` 里登记 `1: v1ToV2`：给每个板块补 `note: ''` 和 `links: []`，`schemaVersion` 改为 2。
- 沿用现有机制：升级前把旧数据另存一份到 `personal-os:data:backup-v1`；导入版本 1 的备份时同样先升级再校验。
- `CURRENT_SCHEMA_VERSION` 改为 2；`AppData.schemaVersion` 的类型改为 `2`。
- 示例数据给每个板块补上 `note` 和 `links`（内容全部虚构，网址用 `https://example.com` 一类保留域名）。

### 2.4 状态（store）

- `updateLane` 的补丁类型扩展到 `name | color | note`。
- 新增 `addLink(laneId, { title, url }): string`、`updateLink(laneId, linkId, patch)`、`removeLink(laneId, linkId)`。三者都进入撤销历史（每次一步）。
- 板块被删除时，它的备注和链接随板块一起消失（因为就在板块上），不需要额外的级联逻辑。
- `addLane` 创建的新板块带 `note: ''` 和 `links: []`。

## 3. 路由

- 路由由“页面名”扩展为“页面名加可选参数”：`#/modules` 和 `#/modules/<板块编号>`。其他路由不变。
- `useHashRoute` 在返回路由名的同时返回参数。参数只对 `modules` 有意义，其他路由忽略它。
- 所选板块的规则：参数指向存在的板块就选它；参数缺失或指向不存在的板块，选排在第一位的板块；没有任何板块时显示空状态（同全局页的空状态）。
- 选中板块就是改变网址（`#/modules/<id>`），所以浏览器的后退、刷新、复制链接都有效。
- 主页的板块概览卡改成指向 `#/modules/<id>` 的链接，整张卡可点，键盘可聚焦。

## 4. 页面

沿用全局页的视觉：画布底色、白色卡片加柔和阴影、Inter 加思源黑体，标题用思源宋体。最小宽度 1024 像素不变。

### 4.1 左侧：板块列表

- 宽 240 像素。每行：板块色点、名称、一行小字显示当前阶段名（没有则“暂无进行中阶段”）。
- 当前所选的行用该板块的色带第 3 级做底，名称加粗。
- 底部“添加板块”按钮，沿用 `addLaneAndRename`；新建后自动选中它。
- 板块的顺序以 `order` 为准。

### 4.2 右侧：所选板块的详情

自上而下四块，每块一张卡片：

1. **标题区**：板块名（思源宋体大标题）加板块菜单（复用 `LaneMenu`：改名、换色、上移、下移、删除）。下面一行摘要，内容和主页板块概览卡一致：当前阶段、进度、下一个节点、下一阶段（复用 `summarizeLane`）。
2. **备注**：多行文本框，最多 2000 字，失焦时保存，保存进入撤销历史；没有内容时显示灰色提示“写点什么：目标、注意事项……”。输入超长时不截断，显示剩余字数并阻止保存。
3. **资料链接**：
   - 列表行：标题，右侧小字显示域名，整行是一个链接，在新标签页打开，带 `target="_blank"` 和 `rel="noopener noreferrer"`。
   - 行尾两个按钮：修改、删除。修改就地展开为标题和网址两个输入框，回车或点“保存”提交，`Esc` 取消。
   - 顶部“添加链接”展开同样的两个输入框。网址经 `normalizeLinkUrl` 规范化；不合法时在输入框下方提示“请输入以 http 或 https 开头的网址”，不保存。
   - 删除不弹确认，沿用底部“已删除，撤销”提示条。
   - 没有链接时显示一句空状态。
4. **阶段与节点**：
   - 顶部两个按钮“添加阶段”“添加节点”，在**当前板块**里新建（阶段默认四周、从本周一起；节点默认今天），并立即打开编辑面板且选中名称。
   - 阶段和节点按时间顺序混排：阶段按开始日期，节点按日期。
   - 每行：类型图标（色块或圆点）、名称、日期（阶段显示起止，节点显示日期）、状态标签。状态：阶段为“进行中”“待确认”“未开始”“已结束”，节点为倒计时文字（“还有 N 天”“就是今天”“已过 N 天”，沿用 `countdownText`）。
   - 已结束的项（阶段结束日在今天之前或当天，节点日期早于今天）默认折叠成一行“已结束 N 项”，点击展开。当前有选中或正在编辑的已结束项时自动展开。
   - 点一行：选中并打开现有的阶段或节点编辑面板（`PhaseEditor`、`MilestoneEditor`），行为和在时间线上点一致。
   - 板块没有任何阶段和节点时显示空状态。

### 4.3 键盘

- 板块列表：上下方向键在行间移动，回车选中。
- 详情里所有按钮和行都可以用 `Tab` 到达，焦点样式沿用现有的。
- 时间线专用的快捷键（方向键移动选中项、`Delete`、`T`）在本页不启用，避免误操作；撤销重做（`Ctrl+Z`、`Ctrl+Shift+Z`）保持可用。

## 5. 代码结构

新增 `features/lane/`，其余尽量复用：

```
src/
  data/
    links.ts           normalizeLinkUrl（纯函数）
    migrations.ts      登记 1→2
    schema.ts          Link、Lane 扩展、版本 2
    store.ts           updateLane 补丁扩展，addLink/updateLink/removeLink
    sample.ts          示例数据补备注和链接
  features/
    lane/
      LanePage.tsx     页面：左右两栏、选中逻辑、空状态
      LaneSidebar.tsx  板块列表
      LaneHeader.tsx   标题区和摘要（复用 summarizeLane）
      NoteCard.tsx     备注
      LinksCard.tsx    资料链接
      ItemsCard.tsx    阶段与节点列表
      items.ts         合并、排序、分组、状态文字（纯函数）
    home/
      LaneOverview.tsx 卡片改成链接
  app/
    useHashRoute.ts    路由加参数
    App.tsx            modules 路由挂上 LanePage
```

边界约定沿用第一版：`data/` 不依赖界面；`items.ts` 和 `links.ts` 是纯函数；`features/lane` 只读数据、发出修改意图。编辑面板仍由 `editorStore` 控制，`LanePage` 像 `Timeline` 一样渲染它们。

## 6. 出错处理

| 情况 | 处理 |
|---|---|
| 链接网址不合法 | 输入框下方提示，不保存 |
| 备注超过 2000 字 | 显示剩余字数，阻止保存，已输入内容保留 |
| 导入的备份里有不合法的链接（例如 `javascript:`） | 整体拒绝，提示“备份文件内容不完整或已损坏”，现有数据不变 |
| 路由参数指向不存在的板块 | 选第一个板块，不报错 |
| 当前板块被删除或撤销后消失 | 选中回到第一个板块 |
| 升级 1→2 失败 | 沿用现有处理：保留旧数据和 `backup-v1`，显示数据读取失败页 |

## 9. 已知风险

- **数据版本升到 2 之后，旧版应用打不开新数据。** 因为是单人使用、同一个网址，刷新即可拿到新版；已有的“导入文件版本比应用新则拒绝”的保护会在极端情况下给出提示。
- **链接是用户自己填的外部网址。** 用协议白名单和 `noopener noreferrer` 防止脚本注入和反向控制；应用本身不抓取、不预览这些网址，所以不会向外发请求。
- **备注是纯文本。** 不渲染任何标记，所以没有注入风险；代价是不能排版，是有意的取舍。
